# IPTV

Небольшой REST API на Go: отдаёт абоненту список ТВ-каналов и ссылку на live-поток.
Хранилище — PostgreSQL, аутентификация — HTTP Basic Auth.

## Запуск

Через Docker (самый простой способ):

```bash
docker compose up --build
```

Локально (нужны Go 1.26+ и PostgreSQL):

```bash
go mod tidy                      # один раз: подтянуть зависимости и создать go.sum
export DATABASE_URL='postgres://iptv:iptv@localhost:5432/iptv?sslmode=disable'
go run ./cmd/server
go test ./...                    # тесты HTTP-слоя, БД не нужна
```

Схема создаётся автоматически при старте, тестовые данные
добавляются, только если таблицы пусты.

### Настройки (переменные окружения)

| Переменная        | По умолчанию                                               | Назначение                          |
| ----------------- | ------------------------------------------------------------ | ----------------------------------- |
| `LISTEN_ADDR`     | `:8080`                                                       | адрес HTTP-сервера                  |
| `DATABASE_URL`    | `postgres://iptv:iptv@localhost:5432/iptv?sslmode=disable`   | подключение к PostgreSQL            |
| `STREAM_BASE_URL` | `http://stream.example.com`                                   | базовый адрес стримингового сервера |

## Тестовые данные

| Пользователь | Пароль     | Активен |
| ------------ | ---------- | ------- |
| `ivan`       | `ivan123`  | да      |
| `anna`       | `anna123`  | да      |
| `dmitry`     | `dmitry123`| **нет** |

Каналы: «Первый», «Россия 1», «Матч ТВ», «НТВ», «ТНТ» (активны) и «Архивный канал» (**выключен**, id 6).

## API

```bash
curl -u ivan:ivan123 http://localhost:8080/api/v1/channels
curl -u ivan:ivan123 http://localhost:8080/api/v1/channels/1/playback
```

`GET /api/v1/channels`:

```json
{"channels": [{"id": 1, "number": 1, "name": "Первый"}, {"id": 2, "number": 2, "name": "Россия 1"}]}
```

`GET /api/v1/channels/{id}/playback`:

```json
{
  "channel_id": 1,
  "url": "http://stream.example.com/live/ch1/index.m3u8"
}
```

Ошибки всегда в одном формате, без внутренних подробностей:

```json
{"error": {"code": "channel_not_found", "message": "channel not found"}}
```

| Ситуация                                      | Ответ                                           |
| --------------------------------------------- | ----------------------------------------------- |
| нет/неверные учётные данные, пользователь выключен | `401` + `WWW-Authenticate: Basic realm="iptv"` |
| `id` не положительное целое (`abc`, `0`, `-1`, переполнение) | `400` `invalid_id`                |
| канал не существует или выключен              | `404` `channel_not_found`                       |
| неизвестный путь                              | `404` `not_found`                               |
| не `GET`                                      | `405` + `Allow: GET`                            |
| сбой БД и прочее                              | `500` `internal_error` (детали только в лог)    |

## Принятые решения

**Пароли** хранятся как bcrypt-хеш. Для несуществующего логина bcrypt
всё равно выполняется (с фиктивным хешем), поэтому по времени ответа нельзя понять, существует ли
пользователь. Клиент во всех случаях отказа получает одинаковый 401.

**Ссылка на поток.** Реального стримингового сервера нет, поэтому ссылка просто корректно
сформированный URL плейлиста, без подписи и срока действия. В базе хранится не готовый URL, а
`stream_slug` канала; ссылка строится как `{STREAM_BASE_URL}/live/{slug}/index.m3u8`
(`controller/stream.go`). Доступ к самому эндпоинту всё равно защищён Basic Auth.

**Выключенный канал → 404**, а не 403: для абонента его «нет», и API не раскрывает, что такой канал есть.
Выключенный канал не попадает и в список.

**Список** отсортирован по `number`; если каналов нет, возвращается `[]`, а не `null`.

**Структура.**

```
cmd/server/                 запуск, сборка зависимостей, graceful shutdown
internal/config/            настройки из переменных окружения
internal/dto/               структуры данных: User, Channel, ответы API, формат ошибок, ErrNotFound
internal/adapter/postgres/  всё, что касается БД
    postgres.go             подключение (пул, ожидание доступности БД)
    migrate.go              схема
    seed.go                 тестовые данные
    users.go                запросы к users
    channels.go             запросы к channels
internal/controller/        всё, что касается HTTP-сервера
    controller.go           маршруты, зависимости (интерфейсы хранилища)
    channels.go             обработчики эндпоинтов
    middleware.go           Basic Auth, логирование, recover, проверка метода
    response.go             JSON-ответы и ошибки
    stream.go               сборка ссылки на HLS-плейлист
```

Контроллер зависит от интерфейсов хранилища, а не от PostgreSQL, поэтому тестируется без БД
(`internal/controller/controller_test.go`). Маршрутизация — стандартный `net/http` ( из внешних зависимостей только `pgx` и `x/crypto`.
